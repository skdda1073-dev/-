# 💡 개발자 수칙 및 프로젝트 규칙 (hallym_capstone)

> **최우선 원칙**: 모든 작업 전 **사전 설명 및 동의**, 그리고 **1파일 = 1기능 모듈 분리 원칙**을 철저히 준수한다. 개발 작업을 진행하기 전에는 **반드시 "무엇을 왜 하려는 것인지" 사용자에게 사전에 설명하고 확인을 받은 뒤**에만 진행한다.

---

## 🎯 1. 프로젝트 개요 (Overview)
* **프로젝트명**: 춘천 대학생 통학 마스터 (hallym_capstone)
* **플랫폼 정체성**: Python Flask 백엔드 기반의 모바일/PC 반응형 웹(Web) 서비스
* **핵심 기능**: 실시간 GPS 및 캠퍼스 건물 기반 출발지 설정, TMAP 도보 시간 계산, 공공데이터 버스 도착 정보 연동, 맞춤형 승차 가이드(여유/촉박/다음차) 및 최적 정류장 단일 카드 추천

## 💻 2. 코딩 & 아키텍처 규칙 (Coding Standards)
1. **단일 책임 원칙 (1 파일 = 1 기능/모듈)**:
   * 하나의 파일에 여러 기능을 섞지 않는다.
   * 코드가 엉키거나 수정 시 다른 기능이 부서지는 부작용을 막기 위해 모든 파일은 단 하나의 명확한 역할만 담당하도록 분리한다.
2. **Flask 표준 폴더 구조 엄수**:
   * `templates/index.html`: 순수 HTML 레이아웃 뼈대만 유지 (내부에 긴 `<style>`이나 `<script>` 작성 금지)
   * `static/css/`: 디자인 스타일 분리 (`main.css`, `result-card.css`, `timeline.css` 등)
   * `static/js/`: 프론트엔드 로직 분리 (`api-service.js`, `gps-controller.js`, `search-controller.js`, `ui-renderer.js` 등)
   * `services/` (또는 백엔드 모듈): `app.py`가 비대해지지 않도록 API 호출 및 시간 계산 로직 분리
3. **독립성 보장**: 하나의 파일(모듈)을 수정하더라도 다른 모듈이나 기존 UI 렌더링에 에러가 나지 않도록 작성한다.
