# 공공데이터 기반 버스 경로 계산

## 실행 전 환경변수 설정

실제 API 키는 저장소·문서·채팅에 넣지 않는다. 개발 환경의 터미널에서 아래 변수에 각자 발급받은 값을 설정한 뒤 서버를 실행한다.

```bash
export NAVER_MAP_CLIENT_ID='네이버 지도 클라이언트 ID'
export TMAP_APP_KEY='TMAP 앱 키'
export PUBLIC_DATA_KEY='공공데이터포털 인증키'
python3 app.py
```

로컬 `.env` 파일을 사용한다면 해당 파일은 Git에 올리지 않는다. 이 프로젝트는 `.env`를 자동으로 읽지 않으므로, 실행 전에 셸에서 변수를 내보내거나 사용하는 도구에서 같은 환경변수를 주입해야 한다.

현재 런타임은 `NAVER_MAP_CLIENT_ID`, `TMAP_APP_KEY`, `PUBLIC_DATA_KEY`만 사용한다. 네이버 지도 클라이언트 시크릿은 이 앱의 현재 기능에 필요하지 않으므로 설정하거나 공유하지 않는다.

## 구현 범위

대중교통 길찾기 서비스의 결과를 가져오는 대신 TAGO의 정류소·노선·노선별 경유 순서를 이용해 직접 후보를 계산한다. 지도 표시는 기존 네이버 지도를, 접근·하차 후 도보 시간은 기존 TMAP 보행 경로를 이용한다. 별도의 TMAP 대중교통 상품은 사용하지 않는다.

이번 버전은 춘천의 출발지·목적지 반경 500m 정류장 중 각각 가까운 8개, 최대 32개 노선, 직통 및 **동일 정류장 ID에서의 1회 환승**을 지원한다. 양쪽 길의 서로 다른 정류장 사이를 걸어서 환승하거나 2회 이상 환승하는 경로는 검색하지 않는다. 범위를 제한한 후보이므로 네이버 지도와 동일한 결과나 전역 최단 경로를 보장하지 않는다.

## 먼저 확인할 API 권한

작성 시점인 2026-10-15의 실제 조회에서 기존 키로 정류소·경유노선은 HTTP 200/결과 00이었지만, `BusRouteInfoInqireService/getRouteAcctoThrghSttnList`는 **HTTP 403**이었다. 포털의 현재 키·활용신청 승인·사용기한 상태를 확인해야 실제 경로를 검증할 수 있다.

1. [공공데이터포털 TAGO 버스노선정보](https://www.data.go.kr/data/15098529/openapi.do)에 로그인한다.
2. 해당 서비스의 활용신청 및 승인을 확인한다. 기존 ‘버스정류소정보’·‘버스도착정보’와 별도 서비스이다.
3. `노선별경유정류소목록 조회`가 승인된 인증키로 동작하는지 확인한다. 키 값은 채팅·캡처·GitHub에 올리지 않는다.
4. 기존 앱의 인증키로 승인되었다면 별도 키 추가 없이 Flask 서버를 다시 실행하고 조회한다. 다른 키가 발급되었다면 환경변수로 분리하는 별도 설정 작업을 한다.

권한이 없는 경우 경로 응답은 HTTP 502와 `code: ROUTE_PERMISSION`을 반환하고 화면에 활용신청 안내를 표시한다. 이전의 노선번호 교집합 방식으로 돌아가 잘못된 경로를 표시하지 않는다.

## 파일의 책임

| 파일 | 역할 |
| --- | --- |
| `app.py` | 입력 좌표·캠퍼스를 검증하고 서비스 호출 및 JSON 응답 |
| `services/public_transit_client.py` | HTTPS TAGO 조회, 전체 페이지 수집, 오류 정규화, 정적 데이터 메모리 캐시 |
| `services/walking_service.py` | TMAP 보행 경로 시간·거리 조회와 메모리 캐시 |
| `services/transit_service.py` | 출발·목적지 정류장 후보와 노선 순서 수집, 도보·도착정보 연결 |
| `services/route_planner.py` | 외부 호출 없는 직통·1회 환승 탐색과 소요시간 계산 |
| `static/js/search-controller.js` | 장소 선택과 이전 장소 검색·경로 요청 취소 |
| `static/js/api-service.js` | 경로 요청과 오래된 응답 차단, 지도 실패와 결과 카드 표시 분리 |
| `static/js/ui-renderer.js` | 후보별 승하차·도보·대기·추정 시간 표시 |
| `static/js/map-controller.js` | 첫 후보의 출발·도착·승하차·환승 정류장 및 연결선 표시 |
| `static/css/result-card.css` | 경로 후보 카드 스타일 |

기존 목적지 장소 검색 공급자(TMAP POI)와 CSV 원본 데이터는 유지한다. `main.js`와 GPS 권한 처리 모듈도 유지한다. 검색 결과에서 잘못된 장소를 선택했다면 이 경로 계산 개선만으로 좌표 자체가 바뀌지는 않으므로, 장소명·주소를 확인해야 한다.

## 계산 과정

1. 출발지와 목적지의 GPS 반경 500m 정류장을 조회하고 숫자 좌표와 도시코드를 확인한다.
2. 출발·도착 후보에 정차하는 정확한 `routeid`를 수집한다. `routeno`가 같다는 이유로 다른 노선을 연결하지 않는다.
3. 노선별 경유 정류장을 `totalCount`까지 모든 페이지에서 읽는다. 중복 페이지·누락 페이지는 오류로 처리한다.
4. `nodeord`가 유효하고 중복되지 않는지 확인한 뒤, `updowncd`가 동일한 연속 구간에서 승차 뒤 하차가 오는 경로만 만든다. 누락된 방향·좌표 구간이나 방향 전환 경계를 연결하지 않는다. 순환 노선의 끝과 처음도 자동 연결하지 않는다.
5. 1회 환승은 첫 노선의 하차 ID와 다른 노선의 승차 ID가 정확히 같은 경우만 연결한다. 같은 노선 ID 또는 같은 번호로 바꿔 타는 경우는 이 버전에서 제외한다.
6. 출발지→승차 정류장과 하차 정류장→목적지의 실제 보행 경로를 구한다. 보행 조회에 실패한 후보는 제외한다.
7. 각 경유 정류장 사이 거리를 합산해 버스 시간을 추정하고, 새 실시간 도착정보로 첫 버스를 탈 수 있는지 확인한다.
8. 확인된 배차가 있어 총시간을 계산할 수 있는 후보를 먼저 표시하고, 그 안에서 총시간으로 정렬한다. 미확인 배차가 있으면 알려진 구간의 추정 시간만 비교한다. 최대 3개 후보를 반환한다.

## 시간의 의미와 한계

- 버스 시간은 실제 도로 경로가 아니라 **정류장 사이 연속 직선거리 합 × 1.2**, 평균 시속 20km 및 중간 정류장당 0.4분 정차시간으로 추정한다. 이 값은 실측이 아니며 향후 운행 기록으로 보정해야 한다.
- 도보 시간은 초를 분으로 올림한다. 실패를 0분으로 바꾸지 않는다.
- 첫 버스의 도착 예정시간이 접근 도보 + 1분 승차 여유보다 이르면 그 버스를 탈 수 있다고 판정하지 않는다. 이후 배차를 알 수 없으면 대기를 미확인으로 둔다.
- 1회 환승에는 2분의 환승 여유를 둔다. 두 번째 버스의 미래 배차는 현재 도착정보만으로 확정하지 않는다. 따라서 이 버전의 환승 경로는 전체 ETA가 미확인이다.
- 같은 정류장이 노선에 여러 번 나와 차량의 방문 차례를 구분할 수 없으면 실시간 대기도 미확인으로 둔다.
- `total_min`이 숫자면 알려진 대기까지 포함한 **추정 총시간**이다. `null`이면 `known_min`에 알려진 도보·추정 버스·환승 여유·확인된 대기만 넣고, 화면에 ‘배차 대기 미확인’을 표시한다.
- 지도상의 선은 **정류장 연결선**이다. 실제 버스 주행 궤적이나 도보 길을 그린 것이 아니다.
- 정확한 요금 데이터가 없어 과거의 고정 요금 문구를 제거했다.

## 응답 계약

목적지가 없으면 기존 주변 정류장 배열을 유지한다. 목적지가 있으면 아래 형식이다.

```json
{
  "mode": "journeys",
  "origin": {"name": "출발", "lat": 37.88, "lon": 127.73},
  "destination": {"name": "도착", "lat": 37.86, "lon": 127.72},
  "journeys": [],
  "warnings": [],
  "search": {"max_transfers": 1, "nearby_radius_m": 500, "max_stops_per_endpoint": 8, "max_routes": 32, "max_refined_candidates": 80}
}
```

각 후보에는 `legs`, `access_walk`, `egress_walk`, `transfer_count`, `total_min`, `known_min`, `walk_min`, `ride_min`, `wait_min`, `has_live_departure`, `warnings`, `is_estimate`가 들어간다. 빈 후보 목록은 조회 범위에서 경로를 확인하지 못했다는 뜻이며, 도시 전체에 버스가 없다는 뜻이 아니다.

## 검증

Python 표준 테스트 실행:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
git diff --check
```

테스트는 외부 API를 호출하지 않고 고정 데이터로 검증한다. 역방향·동일 번호 다른 ID·방향 전환·순환 방문·누락된 정류장 순서·환승·놓친 버스·도보 실패·페이지 누락·권한 오류 등을 포함한다. 실서비스의 춘천 경로 정확도는 API 활용 권한을 해결한 뒤 별도로 확인해야 한다.

브라우저 확인 항목:

- 목적지 없는 기존 정류장 목록이 표시되는지
- 직통 후보의 승차→하차 순서와 하차 후 도보가 맞는지
- 1회 환승 후보가 같은 정류장에서만 연결되고 미확인 대기를 표시하는지
- 빠른 목적지 입력·선택·취소·캠퍼스 전환에 이전 응답이 덮어쓰지 않는지
- 지도 SDK 로드 실패에도 결과·오류 카드가 표시되는지
- `ROUTE_PERMISSION` 오류에서 과거 지도 마커가 남지 않는지
- 실제 출발·도착 장소와 조회 시각을 고정해 네이버 지도와 비교하고 차이의 이유를 기록하는지
