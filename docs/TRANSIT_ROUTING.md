# CSV 기반 춘천 버스 경로 계산

## 이번 변경으로 되는 일

사용자가 제공한 춘천 버스 정류장·노선 CSV를 프로젝트에 보관하고, 정류장 검색·경유 노선·정류장 순서를 이 파일에서 읽는다. 노선정보 API의 활용신청 또는 인증키가 없어도 **CSV의 순서를 따르는 직통·1회 환승 후보**를 계산한다.

CSV에는 상·하행, 종점 회차의 연속 탑승 가능 여부, 시간표가 없다. 따라서 결과는 실제 운행이 확인된 길찾기가 아니라 확인이 필요한 경로 후보다. 네이버 지도와 같은 결과나 도시 전체 최단 경로를 보장하지 않는다. 승차 방향과 종점·회차에서 계속 탑승 가능한지 확인해야 한다.

## API 키가 필요한 부분

| 기능 | 데이터 또는 설정 | 키가 없을 때 |
| --- | --- | --- |
| 정류장·노선·정류장 순서 | `data/chuncheon_bus_routes_20260326.csv` | API 키 없이 읽음 |
| 지도 화면 | `NAVER_MAP_CLIENT_ID` | 지도 SDK를 사용할 수 없음. 결과 카드는 별도로 표시 |
| 일반 장소 검색, 실제 도보 시간·거리 | `TMAP_APP_KEY` | 캠퍼스 건물 검색은 가능. 외부 장소 검색과 일반적인 도보 구간은 확인 불가 |
| 실시간 버스 도착 참고값 | `PUBLIC_DATA_KEY` | CSV 후보는 표시하되 도착·대기·총시간을 미확인으로 둠 |

네이버 지도 키는 TMAP 보행 조회나 실시간 버스 도착 키를 대체하지 않는다. 별도 TMAP 대중교통 길찾기 상품은 이 구현에서 사용하지 않는다. 실제 키 값은 저장소·채팅·캡처에 올리지 않는다.

출발지와 승차 정류장, 하차 정류장과 목적지가 각각 **완전히 같은 좌표**면 해당 도보는 0분이므로 키 없이도 확인할 수 있다. 일반 GPS·건물 출발은 정류장까지 걸어야 하므로 TMAP 보행 설정이 필요하다. 도보 조회 실패를 직선거리 시간이나 가짜 0분으로 대체하지 않는다.

## 실행 방법

현재 버전은 프로젝트 루트의 `.env`를 자동으로 읽는다. 실제 키 입력·가상환경 설치·실호출 점검 순서는 `BACKEND_SETUP.md`를 우선 따른다. 아래 환경변수 방식도 유지하며, 터미널의 명시적 설정이 `.env`보다 우선한다.

기존 Python 환경과 프로젝트 의존성이 설치되어 있다는 전제다. 새 PC는 프로젝트 폴더에서 먼저 `python -m pip install -r requirements.txt`를 실행한다. Windows는 `python` 대신 `py`, macOS는 `python3`를 사용할 수 있다.

macOS의 VS Code 터미널:

```bash
export NAVER_MAP_CLIENT_ID='본인 네이버 지도 클라이언트 ID'
export TMAP_APP_KEY='본인 TMAP 앱 키'
# 실시간 도착이 필요할 때만 설정
export PUBLIC_DATA_KEY='본인 공공데이터포털 인증키'
python3 app.py
```

Windows PowerShell의 VS Code 터미널:

```powershell
$env:NAVER_MAP_CLIENT_ID = '본인 네이버 지도 클라이언트 ID'
$env:TMAP_APP_KEY = '본인 TMAP 앱 키'
# 실시간 도착이 필요할 때만 설정
$env:PUBLIC_DATA_KEY = '본인 공공데이터포털 인증키'
py app.py
```

현재 로컬 브라우저 접속 주소는 `http://localhost:5050`이다. 이 주소에서 네이버 지도 표시를 확인했으며 `127.0.0.1`로 접속하면 지도 인증에 실패했다. `PORT` 설정이 없을 때 코드 기본값은 5000이다. 위 키 값은 예시 설명이므로 발급받은 실제 값으로 바꾸어야 한다. 환경변수는 서버 실행 전에 설정하고, 바꾼 뒤에는 서버를 다시 시작한다. 실행 전 의존성을 설치한 프로젝트 가상환경을 활성화하거나 해당 Python 실행 파일을 사용한다. 네이버 지도 클라이언트 시크릿은 현재 코드에서 사용하지 않는다.

## 계산 규칙

1. 원본을 UTF-8 BOM 또는 CP949로 읽고 필수 열·좌표·기준일·ID를 검증한다. 파일이 없거나 손상되면 `CSV_DATA` 오류를 표시한다. 실패 시 노선 API로 몰래 돌아가지 않는다.
2. 출발지·목적지 반경 500m의 가까운 정류장을 각각 최대 8개 선택한다.
3. 정류장과 노선은 이름이나 버스번호가 아닌 ID로 연결한다. CSV 숫자 ID에 춘천 TAGO 접두사 `CCB`를 붙인다. 실시간 자료도 정확한 ID가 일치할 때만 사용한다.
4. CSV의 `정류장순서`가 연속으로 증가하는 구간만 연결한다. 역순 이동, 마지막→처음 자동 연결, 중간 순번을 회차로 가정하는 처리는 하지 않는다. 반복 방문은 각각 보존한다.
5. 상·하행 없는 처리는 `sequence_basis: csv_order`가 명시된 자료에만 허용한다. 기존 API 자료는 방향 검증을 유지한다.
6. 서로 다른 노선 ID·번호 사이에서 **동일 정류장 ID의 1회 환승**만 허용한다. 다른 ID의 맞은편 정류장이나 이름이 같은 정류장을 합치지 않는다.
7. 출발·도착 주변 정류장의 노선 순서를 로컬에서 읽는다. 현재 CSV는 223개 노선이며 API 호출량용 32개 제한을 CSV에는 적용하지 않는다. 보행 후보 비교는 최대 80개로 제한하고 최대 3개를 표시한다.
8. 접근·하차 후 실제 보행 조회에 실패한 정류장은 제외한다. 출발 또는 도착 쪽 모든 보행이 실패하면 `WALK_UNAVAILABLE`로 설명한다.
9. 보행 조회 뒤 새 실시간 도착정보를 받는다. CSV는 방향이 미검증이므로 도착값은 참고용일 뿐 탑승 가능 판정이나 총 ETA에 쓰지 않는다. 방문 차례가 여러 개인 승차 정류장은 참고값도 붙이지 않는다.
10. 두 번째 버스의 미래 배차는 현재 도착정보로 추측하지 않는다.

## 시간과 지도 표시

- 버스 구간 시간은 연속 정류장 직선거리 합 × 1.2, 평균 시속 20km, 중간 정류장당 0.4분 정차로 추정한다. 시간표·실제 도로·교통량을 반영한 값이 아니다.
- `known_min`은 확인된 도보와 추정 버스 구간, 환승 여유 2분을 더한 값이다. CSV 후보의 `total_min`과 `wait_min`은 `null`이다. 전체 도착 예정시간으로 해석하면 안 된다.
- CSV 후보는 카드 제목에 “운행 확인 필요”, 시간 옆에 “방향·회차·배차 미확인”을 표시한다.
- 실시간 도착 `arrival_min`이 있어도 `arrival_reference_only: true`면 해당 정류장·노선의 참고값이다. 상·하행이나 실제 승차 가능 여부를 검증한 값이 아니다.
- 노선번호 미확인 항목은 원래 번호를 추측하지 않고 노선 ID를 표시한다.
- 지도는 첫 번째 후보만 표시한다. 점선은 **정류장 연결선**이며 실제 버스 주행·도보 궤적이 아니다.

## 응답 계약

목적지가 없으면 기존 정류장 배열을 유지한다. 도착 API 실패는 배열 항목의 `arrival_error`로 안내한다. 목적지가 있으면 다음 형식이다.

```json
{
  "mode": "journeys",
  "origin": {"name": "출발", "lat": 37.88, "lon": 127.73},
  "destination": {"name": "도착", "lat": 37.86, "lon": 127.72},
  "journeys": [],
  "source": {
    "source": "csv",
    "sequence_basis": "csv_order",
    "direction_verified": false,
    "data_dates": ["2025-02-12", "2026-03-26"]
  },
  "warnings": [],
  "search": {
    "max_transfers": 1,
    "nearby_radius_m": 500,
    "max_stops_per_endpoint": 8,
    "max_routes": 223,
    "max_refined_candidates": 80
  }
}
```

각 후보에 `legs`, `access_walk`, `egress_walk`, `transfer_count`, `known_min`, `total_min`, `total_unavailable_reason`, `warnings`가 포함된다. CSV 후보의 이유는 `direction_unverified`이다. 빈 목록은 제한된 범위에서 후보를 찾지 못했다는 뜻이다.

주요 오류는 `CSV_DATA`(파일·형식), `WALK_UNAVAILABLE`(보행 설정·조회)이며 HTTP 502로 반환한다. 실시간 키가 없는 `ARRIVAL_KEY_MISSING`은 경로 전체를 실패시키지 않고 안내한다.

## 검증 방법

프로젝트 폴더의 터미널에서:

```bash
.venv/bin/python -m unittest discover -s tests
node tests/frontend_smoke.cjs
git diff --check
```

Windows는 첫 줄을 `.\.venv\Scripts\python.exe -m unittest discover -s tests`로 바꾼다. Node.js가 없는 환경에서는 두 번째 검증만 실행할 수 없다. Node는 Flask 실행 필수 의존성이 아니다.

자동 검증은 외부 API를 호출하지 않는다. 실제 CSV의 다음 구간을 검증한다.

| 노선 | 승차 ID | 하차 ID | 이동 정류장 구간 수 |
| --- | --- | --- | --- |
| 12-S: 한림대학교→춘천역 | CCB250002127 | CCB250026552 | 7 |
| 400: 한림대학교→강원대중앙도서관 | CCB250001275 | CCB250026903 | 11 |
| 400 귀로: 강원대중앙도서관→한림대학교 | CCB250026904 | CCB250002127 | 10 |

그 밖에 역방향·끝→처음 금지, 반복 방문, 순번 누락·중복, 손상된 번호, 정류장 좌표 충돌, 키 없이 CSV 조회, 보행 실패 구분을 검증한다. 프런트엔드는 가상 DOM·지도 모의 객체로 검증하며 실제 브라우저·SDK 검증을 대신하지 않는다.

2026-10-16 실제 키를 사용한 로컬 점검에서 TMAP 장소 검색 8건, 보행 조회를 포함한 CSV 후보 3개, 공공데이터 버스 도착 API 정상 응답을 확인했다. 브라우저에서 한림대 건물 → 춘천역 검색·선택·후보 카드 표시를 확인했고, `localhost:5050`에서 네이버 지도와 출발 마커가 표시됐다. 도착자료가 빈 목록이어서 운행 중 버스의 실제 도착값은 검증하지 못했다. 따라서 실제 GPS와 운행 중 도착 시각까지 전체 검증됐다고 해석하면 안 된다. 다음 항목은 실제 브라우저·운행 중 환경에서 추가 확인한다.

- 한림대 건물/GPS 출발과 춘천역·강원대 도서관 목적지 선택 시 후보·하차 정류장이 맞는지
- 반대편 정류장을 섞지 않는지, 종점 회차를 걸치는 후보가 실제로 연속 탑승 가능한지
- 빠른 검색·선택·취소·캠퍼스 전환에 이전 응답이 덮어쓰지 않는지
- 도착 API 실패에도 후보가 남고, 지도 SDK 실패에도 카드·오류 안내가 보이는지
- 동일 출발·목적지·조회 시각으로 네이버 지도와 비교하고 차이와 검색 범위 제한을 기록했는지

## 평가 전 필요한 데이터 보완

권오준은 날짜처럼 변형된 번호 9개와 동일 ID 내 번호가 혼재한 노선 1개를 원 제공처와 대조해야 한다. 임의로 `07월 01일`을 특정 번호로 바꾸지 않는다. 상·하행·회차별 운행 구간을 검증한 추가 자료가 있어야 실제 운행이 확인된 직통/환승과 전체 시간을 안내할 수 있다.

원본·기준일·해시는 `data/README.md`에 기록한다. 이번 작업은 로컬 파일 구현·검증까지만 수행하며 커밋·push·main 병합은 별도 단계다.
