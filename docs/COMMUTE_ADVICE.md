# 날씨·대기질 통학 준비 안내

## 이번 기능

기준 버전 `2fa6a48`에 작은 **통학 준비** 안내창을 추가한다. 선택한 출발 캠퍼스의 비·눈 예보와 기온·풍속, 춘천 참고 측정소의 미세먼지 정보를 읽고 준비할 물품을 안내한다. 안내창은 닫았다가 다시 열 수 있으며, 조회가 실패해도 기존 길찾기·셔틀·시외버스·택시 기능은 계속 이용할 수 있다.

날씨는 **한국 시각의 다음 정시부터 6개 시간대 예보**다. 예를 들어 오후 2시 20분에 조회하면 오후 3시부터 오후 8시까지를 확인한다. 밤에는 다음 날 예보도 포함한다. 기온·풍속 숫자는 해당 시각의 예보이며 현재 현장에서 측정한 값으로 표시하지 않는다.

대기질은 기본적으로 **중앙로 측정소의 춘천 참고값**을 사용한다. 한림대·강원대 건물 안이나 교내에서 직접 측정한 값이 아니다. 날씨는 현재 설정한 캠퍼스 좌표를 기준으로 한림대 `(73, 134)`, 강원대 `(73, 133)` 예보 격자를 각각 조회한다. 중앙로 대기질 자료는 두 캠퍼스가 공유한다.

## 먼저 신청할 API

| 필요한 정보 | 공공데이터포털 서비스 | 사용하는 조회 기능 |
| --- | --- | --- |
| 비·눈 예보, 기온, 강수확률, 풍속 | [기상청_단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do) | `getVilageFcst` |
| 미세먼지·초미세먼지 농도와 등급 | [한국환경공단_에어코리아_대기오염정보](https://www.data.go.kr/data/15073861/openapi.do) | `getMsrstnAcctoRltmMesureDnsty` |

두 API는 무료 공공 API다. 공공데이터포털에서 **각 서비스의 활용신청·승인 상태**를 확인한다. 기존 TAGO 시외버스용 키가 있어도 이 두 서비스의 사용 권한까지 승인된 것은 아니다. 이번 첫 버전은 측정소를 지정해서 조회하므로 별도의 측정소정보 API 신청은 필요하지 않다.

기상청에서 읽는 항목은 `TMP`(기온, ℃), `WSD`(풍속, m/s), `POP`(강수확률, %), `PTY`(강수형태)다. 여기서 필요한 바람 정보는 풍량이 아닌 **풍속**이다. 위경도를 기상청 예보 격자 `nx`, `ny`로 바꿔 조회한다.

에어코리아는 `ver=1.3`으로 농도와 `pm10Grade1h`, `pm25Grade1h`를 사용한다. 현재 출발 안내에 쓰는 1시간 등급이므로 24시간 등급 필드와 섞지 않는다. 점검·자료이상·통신장애나 빈 값은 `좋음` 또는 `0`으로 바꾸지 않는다.

## 내 컴퓨터 설정

기존 `.env`와 기존 API 키는 그대로 보존한다. 새 기능은 다음 설정을 읽는다.

| 설정 | 동작 |
| --- | --- |
| `WEATHER_DATA_KEY` | 기상청 서비스에 승인된 키. 비어 있으면 기존 `PUBLIC_DATA_KEY` 사용 |
| `AIRKOREA_DATA_KEY` | 에어코리아 서비스에 승인된 키. 비어 있으면 기존 `PUBLIC_DATA_KEY` 사용 |
| `AIRKOREA_STATION_NAME` | 기본값 `중앙로`. 춘천 참고 측정소 이름 |

같은 공공데이터포털 계정의 `PUBLIC_DATA_KEY`가 이미 설정돼 있으면 두 서비스 신청 후 그 키로 먼저 점검할 수 있다. 별도 키를 사용해야 하면 위 항목만 **개인 `.env`에서 직접** 설정한다. 키 값은 채팅·스크린샷·Git에 올리지 않는다. `.env.example`에는 실제 키를 넣지 않는다. 설정을 바꾼 뒤에는 Flask 서버를 다시 실행한다.

기존 Windows 프로젝트 폴더에서 다음처럼 점검한다.

```powershell
$capstonePython = "..\..\hallym_capstone\.venv\Scripts\python.exe"
& $capstonePython -B .\scripts\check_commute_advice.py
```

기본 실행은 `weather_data_key_configured`, `airkorea_data_key_configured`의 존재 여부만 출력한다. 둘 다 `true`여도 승인·연결 성공까지 확인한 결과는 아니다. 승인 상태를 확인한 다음 실제 조회를 한 번 실행한다.

```powershell
& $capstonePython -B .\scripts\check_commute_advice.py --live --campus hallym
```

강원대 기준은 `--campus knu`로 바꾼다. 실제 조회는 상태·오류 코드·시각·수치·안내 종류만 출력하고 키와 원본 요청 주소는 출력하지 않는다. 매번 별도 프로세스로 실행하는 진단 명령은 웹 서버의 메모리 캐시를 공유하지 않으므로 반복 실행할 필요는 없다.

앱 실행 명령은 기존과 같다.

```powershell
& $capstonePython -B -m flask --app app:app run --host 127.0.0.1 --port 5051 --no-reload
```

브라우저에서 `http://127.0.0.1:5051/`을 열고 `Ctrl+F5`로 새로고침한다.

## 안내 문구를 만드는 기준

아래 수치는 **이 앱의 생활 안내 기준**이다. 기상청 특보나 공식 위험 등급 기준을 새로 정의하는 기능은 아니다.

| 확인된 데이터 | 안내 방향 |
| --- | --- |
| 6시간 안에 비·비/눈·소나기 예보, 또는 강수확률 60% 이상 | 해당 예보 시각과 함께 우산 준비 안내. 확률만 높으면 실제로 비가 온다고 단정하지 않음 |
| 눈 예보 | 눈 예보와 이동 시 주의 안내 |
| **같은 예보 시간대**의 기온 5℃ 이하, 풍속 4m/s 이상 | 장갑·목도리 준비 안내 |
| 위의 추위·바람 복합 조건에 해당하지 않으면서 기온 5℃ 이하 | 따뜻한 겉옷 준비 안내 |
| 위의 추위·바람 복합 조건에 해당하지 않으면서 풍속 8m/s 이상 | 바람을 막을 겉옷 준비 안내 |
| 미세먼지 또는 초미세먼지의 유효한 1시간 등급이 나쁨·매우 나쁨 | 확인된 오염물질과 함께 마스크 준비 안내 |
| 자료 누락·지연·연결 실패 | 확인하지 못한 항목을 안내하고 정상·안전으로 표시하지 않음 |

비와 미세먼지 조건이 동시에 해당하면 두 안내를 함께 보여 준다. 기온 최솟값과 풍속 최댓값이 서로 다른 시각이면 한 시각의 추위·바람 조건처럼 합치지 않는다. 앱의 종합 상태가 `partial`이어도 확인된 공급자의 안내는 표시할 수 있다.

## 자료 시각과 캐시

- 화면의 **예보 발표 시각**, **예보 대상 시각**, **대기질 측정 시각**을 구분한다. 서버에서 조회한 시각을 측정 시각으로 쓰지 않는다.
- 공통 서버 캐시는 15분이다. 여러 이용자가 같은 자료를 반복 호출하지 않도록 공유하며, 화면 새로고침도 이 캐시를 사용한다. 실패 응답도 잠시 보관해 요청이 몰리지 않도록 한다.
- 기본 정책상 3시간을 초과한 대기질 자료는 지연으로 처리한다. 오래된 자료로 새 경고를 만들지 않는다.
- 예보 발표 후 6시간을 초과한 날씨 자료도 지연으로 처리하며, 해당 자료로 준비물 안내를 새로 만들지 않는다.
- 기상청과 에어코리아는 독립적으로 처리한다. 한쪽이 실패해도 다른 쪽의 유효한 정보는 남긴다.
- 출발 캠퍼스를 바꾸면 새 캠퍼스에 맞춰 조회한다. 뒤늦게 도착한 이전 요청이 최신 화면을 덮어쓰지 않도록 한다.

## 문제가 생겼을 때

| 진단 결과 | 확인할 것 |
| --- | --- |
| `*_KEY_MISSING` | 개인 `.env`의 전용 키 또는 `PUBLIC_DATA_KEY`가 설정됐는지 확인 |
| `*_PROVIDER_AUTH` | 두 서비스 각각 활용신청이 승인됐는지, 키가 신청한 계정의 것인지 확인. 키 원문은 보내지 않음 |
| `*_PROVIDER_QUOTA` | 공공데이터포털의 사용량 확인. 반복 진단을 멈추고 호출 허용량이 회복된 후 확인 |
| `*_PROVIDER_TIMEOUT`, `*_PROVIDER_NETWORK` | 잠시 후 재시도. 다른 교통 기능은 계속 이용 가능 |
| `*_NO_DATA`, `*_INCOMPLETE`, `*_PARTIAL`, `*_STALE` | 해당 자료의 기준 시각·누락·지연 상태 확인. 키 오류와 구분 |
| `AIR_QUALITY_MEASUREMENT_UNAVAILABLE` | 측정소 점검·결측 여부와 설정된 측정소 확인 |
| `AIR_QUALITY_STATION_INVALID` | `AIRKOREA_STATION_NAME`에 정상적인 측정소 이름이 있는지 확인. 기본값은 중앙로 |

진단 명령 종료 코드는 정상 `0`, 설정·인자 확인 필요 `2`, 조회 불가 `3`, 일부 자료만 확인 `4`다. 일반 화면에 비밀키나 공급자 원문 오류를 표시하지 않는다.

## 검증 범위

자동 검사는 합성 예보·대기질 자료를 사용한다. 비·눈, 추위와 바람의 같은 시각 매칭, 대기질 등급·결측·지연, 한 공급자 실패, 자정 경계, 요청 검증과 캐시를 확인한다. 합성 자료는 실제 서비스 응답으로 대신 제공하지 않는다.

실제 사용자 키의 활용승인 여부와 실시간 공급자 응답은 사용자의 `--live` 결과로 따로 확인해야 한다. 키 없는 화면이 정상적으로 안내된다고 실제 데이터 연결까지 검증된 것은 아니다.

2026-11-23 패키지 검증에서는 Python 검사 439개와 Node 메모리 DOM 검사 41개가 통과했다. 이 환경에서 실제 브라우저를 실행하거나 테스트 서버에 연결하지 못해 브라우저 화면 배치는 검증하지 못했다. 적용 후 안내창 열기·닫기와 캠퍼스 변경을 사용자의 브라우저에서 확인해야 한다.

협업 시 날씨·대기질 서비스와 UI 모듈을 분리해서 수정한다. 공통 연결 지점은 `app.py`, `services/settings.py`, `templates/index.html`, `static/js/main.js`다. 경로 최적화나 경사로 계산은 이 기능의 범위에 포함하지 않는다.
